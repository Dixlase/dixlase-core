# バックアップのコマンド

バックアップは管理画面のほか、コマンドラインからも作れます。このページでは、定期バックアップ、`dls:backup:create` コマンド、署名付きのバックアップ、スクリプトから頼れる機械可読な出力を説明します。

## バックアップを作る

```bash
php artisan dls:backup:create
php artisan dls:backup:create --targets=database
php artisan dls:backup:create --targets=database,media,private --retention=30
```

| オプション | 意味 |
| --- | --- |
| `--targets=` | 対象をカンマ区切りで指定します: `database`、`media`、`private`、`custom`、`logs`。省略すると `logs` 以外のすべてです。 |
| `--retention=` | 保持日数です。空にすると無期限に残します。 |
| `--format=` | `text`(既定)または `json` です。 |

記録済みのバックアップは `dls:backup:list` で一覧できます。

## 定期バックアップ

スケジューラー(毎分 `php artisan schedule:run` を呼ぶ cron)が動いていれば、サイトは自分でバックアップを取ります。サイト側で設定することはありません。新しいインストールは次の設定で始まります。

| 設定 | 既定 |
| --- | --- |
| 定期バックアップ | オン |
| 頻度 | 毎日(毎週にすると日曜日に実行) |
| 時刻 | サーバー時刻の 02:30 |
| 対象 | データベースのみ |
| 保持期間 | バックアップの設定の既定の保持期間。空欄なら 14 日 |

大きなメディアライブラリを毎晩複製してディスクを埋めないよう、既定はデータベースだけにしています。ディスクに余裕があれば、設定画面でほかの対象を足してください。毎日のバックアップは、保持期間の日数ぶん残ります。

**全体設定 > システム > バックアップ > バックアップ設定** で変更したり止めたりできます。スケジューラーは実行のたびに設定を読み直すので、cron を変える必要はありません。

- **整理。** `dls:backup:cleanup` は、定期バックアップのオン・オフにかかわらず毎日 02:15 に動き、保持期間の切れたバックアップを削除します。保持期間はバックアップを作るときに決まるので、既定の保持期間を変えても、効くのはそのあとに作るバックアップだけです。保持期間を付けずに作った手動のバックアップは、整理では消えません。
- **定期バックアップに失敗すると**、管理者への通知メールを 1 回だけ送り(設定されている場合)、バックアップの設定を編集できるメンバーの管理画面に、定期バックアップがまた成功するまで警告のバナーを出します。2 つのコマンドの出力は `storage/logs/backup.log` に書かれます。
- ダッシュボードの **サイトヘルス** は、直前の定期バックアップが失敗したとき、1 回の間隔に 1 日を足した期間(毎日なら 2 日、毎週なら 8 日)バックアップが取られていないとき、スケジューラーが動いていないときに警告します。定期バックアップがオフのときは、オンにするよう勧めます。
- スケジューラーが実行するのは `dls:backup:create --scheduled` です。`--targets` や `--retention` を指定しない限り、対象と保持期間をこの設定から取り、バックアップに定期の印(`metadata.trigger`)を付けます。

## 署名付きのバックアップ

サイトに整合性の鍵(`.env` の `INTEGRITY_KEY`。[監査ログの整合性](audit-log-integrity.md#整合性の鍵)を参照)があると、バックアップは作るときに署名され、復元は何かを変える前に署名を確かめます。

**何を守るか。** バックアップの記録はアーカイブの SHA-256 を持ち、復元はこの 2 つを比べます。これで壊れたアーカイブは見つかりますが、記録は復元がこれから上書きするデータベースの中にあります。バックアップの保存先とデータベースの両方に書き込める人は、別のアーカイブを置き、その記録を一致させられます。署名は、整合性の鍵で作る HMAC-SHA256 で、アーカイブの SHA-256 と、記録のファイル名・対象にかかります。鍵はどのバックアップ対象にも入らない `.env` にあるので、差し替えたアーカイブに検証を通る署名を付けることはできません。整合性の鍵のほかの用途と同じく、同じ `.env` を読むアプリケーションの中で動くコードからは守りません。

**鍵をバックアップに入れない。** 署名した鍵を同梱したバックアップは何も証明しません。`.env`(または鍵の行)の写しは、バックアップの保存先とは別の場所に置いてください。そうすれば、バックアップから作り直したサーバーでも署名を確かめられます。

**復元での扱い:**

| 署名 | 復元 |
| --- | --- |
| 一致する | 進む |
| このサイトに鍵が無い | 署名ができる前と同じく、ハッシュを確かめたうえで進む |
| 無い(サイトに鍵が無かったころのバックアップ) | 明示的に受け入れない限り拒否 |
| 一致しない | 明示的に受け入れない限り拒否 |
| もう設定に無い版の鍵で署名されている | 明示的に受け入れない限り拒否 |

鍵をローテーションしても、古い鍵を `INTEGRITY_PREVIOUS_KEYS` に残している間は、古いバックアップの署名も確かめられます。その鍵で署名したバックアップを残している間は、鍵も残してください。

**確かめられないバックアップを受け入れる。** アーカイブの出どころが分かっている場合、たとえば鍵を作る前に取ったバックアップの場合に限ってください。拒否も受け入れも、すべて監査ログに残ります(`backup_signature_rejected`、`backup_signature_overridden`)。

- コマンドラインでは `php artisan dls:backup:restore <id> --allow-unverified-signature`。`--rollback-of=<id>` にも同じオプションが使えます。
- 管理画面では、バックアップの一覧と復元の履歴が、署名を確かめられないことを示し、確認画面で「このまま復元」「このままロールバック」を選べます。バックアップの詳細画面には署名の状態が出ます。

## 機械可読な出力(`--format=json`)

サイトを変更する直前に SSH 越しに実行するなど、コマンドを非対話的に動かすツールは、文章を読む代わりに結果を JSON で受け取れます。

```bash
php artisan dls:backup:create --targets=database --format=json
```

このモードでは、**stdout に JSON オブジェクトを 1 行で 1 つだけ**書き、ほかには何も書きません。進行状況のメッセージは stderr に出ます。失敗したときもオブジェクトを書くので、スクリプトは常に stdout を解析できます。

```json
{"success":true,"backup_record_id":42,"file_path":"/var/www/html/storage/app/private/backups/dixlase-backup-20261117-093000-database.zip","file_name":"dixlase-backup-20261117-093000-database.zip","file_size":2048,"duration":1.23,"targets":["database"],"hash":"9f86d08...","error":null}
```

### フィールド

次のフィールド名は契約です。リリースで破壊的変更として告知しないかぎり、名前を変えたり削除したりしません。フィールドが増えることはあるので、スクリプトは知らないフィールドを無視してください。

| フィールド | 型 | 意味 |
| --- | --- | --- |
| `success` | 真偽値 | バックアップを作れたら `true` です。 |
| `backup_record_id` | 整数 または `null` | バックアップの記録の ID です。管理画面や `dls:backup:list` でこのバックアップを探すときに使います。失敗時は `null` です。 |
| `file_path` | 文字列 または `null` | バックアップのアーカイブの絶対パスです。失敗時は `null` です。 |
| `file_name` | 文字列 または `null` | アーカイブのファイル名です。失敗時は `null` です。 |
| `file_size` | 整数 または `null` | アーカイブの大きさ(バイト)です。失敗時は `null` です。 |
| `duration` | 数値 または `null` | かかった秒数で、小数第 2 位に丸めます。失敗時は `null` です。 |
| `targets` | 文字列の配列 | 含めた対象です。失敗時は、指定された対象です。 |
| `hash` | 文字列 または `null` | 検証用に記録したアーカイブのハッシュです。失敗時は `null` です。 |
| `error` | 文字列 または `null` | 失敗した理由です。成功時は `null` です。 |

### 終了コード

終了コードはどちらの形式でも同じです。

| コード | 意味 |
| --- | --- |
| `0` | バックアップを作れました。 |
| `1` | バックアップに失敗しました。JSON オブジェクトの `error` に理由が入ります。 |
| `2` | オプションが正しくありません(知らない対象、または知らない `--format`)。知らない対象のときは JSON オブジェクトを書きます。知らない形式のときは、形式が決まっていないのでエラーだけを出します。 |

### 例

```bash
out=$(php artisan dls:backup:create --targets=database --format=json) || {
  echo "backup failed: $(printf '%s' "$out" | jq -r .error)" >&2
  exit 1
}
backup_id=$(printf '%s' "$out" | jq -r .backup_record_id)
```
