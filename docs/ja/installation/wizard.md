# インストールウィザード
インストールウィザードは、Dixlase の初期設定をガイドします。`.env` ファイルで `INSTALLED=false` が設定されている場合に自動的に実行されます。

## 概要

ウィザードは以下のステップで構成されています：

1. **サーバーチェック & 言語** - 要件の確認と言語選択
2. **モード選択** - シンプルまたはアドバンスドインストール
3. **基本設定** - サイト名と管理者アカウント
4. **環境設定** - URL、タイムゾーン、SSL、デバッグ設定
5. **データベース** - 接続設定とテスト
6. **メール** - SMTP 設定と接続・送信・受信テスト
7. **確認** - 全設定のレビュー
8. **完了** - インストールの最終処理

## ステップ 0: サーバーチェック & 言語

最初のアクセス時、ウィザードがサーバー環境をチェックします：

- **PHP バージョン**（8.3以上が必須）
- **必須拡張**（Ctype、cURL、DOM、Fileinfo、JSON、Mbstring、OpenSSL、PCRE、PDO、Tokenizer、XML）
- **オプション拡張**（BCMath）
- **ディレクトリパーミッション**（`storage/`、`bootstrap/cache/`）

各チェックで合格/不合格のステータスが表示されます。すべての必須チェックに合格する必要があります。

このステップでインターフェースの言語（英語/日本語）を切り替えることもできます。

## モード選択

インストールモードを選択します：

| モード | 説明 |
|--------|------|
| **シンプル** | 適切なデフォルト値を事前設定。ほとんどのユーザーに最適。デバッグモードやカスタム管理URLなどの詳細オプションをスキップします。 |
| **アドバンスド** | すべての設定を完全にコントロール。経験豊富な管理者向け。 |

### シンプルモードのデフォルト値

シンプルモードを選択すると、以下の値が自動的に設定されます：

- `APP_ENV` = `production`
- `APP_DEBUG` = `false`
- 管理URL パス = `admin`
- SSL 強制 = `true`

## ステップ 1: 基本設定

| フィールド | 必須 | 説明 |
|-----------|------|------|
| サイト名 | はい | ウェブサイトの表示名 |
| 管理者アカウント名 | はい | スーパー管理者のログインユーザー名 |
| 管理者表示名 | いいえ | 表示名（デフォルトはアカウント名） |
| 管理者メール | はい | 管理者アカウントのメールアドレス |
| 管理者パスワード | はい | 管理者アカウントのパスワード |

ここで作成される管理者アカウントは**スーパー管理者**ロール（最高権限レベル）を持ちます。

## ステップ 2: 環境設定

| フィールド | 必須 | シンプルモード | 説明 |
|-----------|------|--------------|------|
| アプリURL | はい | ユーザー入力 | サイトのドメイン（プロトコルなし） |
| 環境 | はい | `production` | `production` または `local` |
| デバッグモード | はい | `false` | デバッグ出力の有効/無効 |
| 管理URL | はい | `admin` | 管理パネルのパスセグメント（例: `admin` → `https://example.com/admin`） |
| タイムゾーン | はい | ユーザー入力 | サーバーのタイムゾーン（デフォルト: `Asia/Tokyo`） |
| SSL 強制 | はい | `true` | 全トラフィックを HTTPS にリダイレクト |

> **ヒント:** 本番環境では、デバッグモードを常にオフ、SSL 強制を常にオンにしてください。

## ステップ 3: データベース設定

| フィールド | 必須 | デフォルト | 説明 |
|-----------|------|-----------|------|
| 接続 | はい | `mysql` | データベースドライバー |
| ホスト | はい | `mysql`（Docker）/ `127.0.0.1` | データベースサーバーのホスト名 |
| ポート | はい | `3306` | データベースポート |
| データベース | はい | `dixlase` | データベース名 |
| ユーザー名 | はい | `dixlase` | データベースユーザー名 |
| パスワード | いいえ | - | データベースパスワード |
| データ保持 | いいえ | オフ | マイグレーション時に既存データを保持 |

### 接続テスト

**接続テスト**ボタンをクリックして、データベースへの接続性を確認してから次に進みます。ウィザードは指定されたデータベースへの一時的な接続を作成し、成功または失敗を報告します。

### データ保持

- **オフ**（デフォルト）: `migrate:fresh` を実行 — すべてのテーブルを削除して再作成します。新規インストール時に使用してください。
- **オン**: `migrate` を実行 — 新しいマイグレーションのみを適用します。既存データを失わずに再インストールする場合に使用してください。

## ステップ 4: メール設定

| フィールド | 必須 | デフォルト | 説明 |
|-----------|------|-----------|------|
| メーラー | はい | `smtp` | メール送信方法（smtp、sendmail 等） |
| ホスト | はい | - | SMTP サーバーのホスト名 |
| ポート | はい | - | SMTP ポート（25、465、587、1025 等） |
| ユーザー名 | いいえ | - | SMTP 認証ユーザー名 |
| パスワード | いいえ | - | SMTP 認証パスワード |
| 暗号化 | いいえ | `tls` | TLS、SSL、またはなし |
| 送信元アドレス | いいえ | （管理者メール） | デフォルトの送信者アドレス |

### メールテスト

ウィザードでは3段階のテストを提供しています：

1. **接続テスト** - SMTP サーバーに到達可能で接続を受け付けることを確認
2. **送信テスト** - 検証リンク付きのテストメールを送信
3. **受信テスト** - 検証リンクをクリックしてテストメールの受信を確認

3つのテストすべてオプションですが、実施を推奨します。テストを完了せずに先に進むこともできます。

> **Docker ユーザー:** ホストに `mailpit`、ポートに `1025` を使用してください。テストメールは `http://localhost:8025` で確認できます。

## ステップ 5: 確認

確認ページでは、入力したすべての設定のサマリーが表示されます：

- 基本設定（サイト名、管理者アカウント）
- 環境設定（URL、タイムゾーン、SSL）
- データベース設定（ホスト、データベース、ユーザー名）
- メール設定（ホスト、ポート、暗号化）
- メールテスト結果（接続、送信、受信のステータス）

すべての値を慎重に確認してください。設定を修正するには戻るボタンを使用してください。

## ステップ 6: インストール実行

**インストール**をクリックすると、ウィザードは以下の操作を順番に実行します：

1. すべての設定を `.env` ファイルに書き込み
2. 設定キャッシュをクリア
3. データベースマイグレーションを実行（データ保持設定に基づいてフレッシュまたはインクリメンタル）
4. デフォルトデータでデータベースをシード
5. テーマのマイグレーションとシーダーを実行
6. 管理者ユーザーアカウントを作成
7. 基本設定とセキュリティ設定を初期化
8. ストレージシンボリックリンクを作成
9. ファイル整合性ベースラインを生成

この処理には1分程度かかる場合があります。ブラウザを閉じたり、ページを移動しないでください。

## ステップ 7: 完了

インストールが正常に完了すると、以下を含む完了ページが表示されます：

- 管理者ログインページへのリンク
- 設定された管理URL

**最終処理**をクリックすると、`.env` ファイルに `INSTALLED=true` が設定されます。最終処理後、インストールウィザードにはアクセスできなくなります。

## トラブルシューティング

### ウィザードが表示されない

- `.env` ファイルで `INSTALLED=false` が設定されているか確認
- 設定キャッシュをクリア: `php artisan config:clear`

### データベースマイグレーションが失敗する

- データベースユーザーに CREATE、DROP、ALTER、INDEX 権限があるか確認
- データベースが存在し空であることを確認（新規インストールの場合）
- `storage/logs/install.log` ファイルで詳細なエラーメッセージを確認

### メールテストが失敗する

- サーバーから SMTP ホストに到達可能か確認
- SMTP ポートのファイアウォールルールを確認
- Gmail/Office 365 の場合、アカウントパスワードではなくアプリ固有パスワードを使用
- 暗号化タイプがポートと一致するか確認（587 = TLS、465 = SSL）

### インストールがハングする

- PHP の `max_execution_time` を確認（推奨: 300秒）
- `storage/logs/install.log` でエラーを確認
- マイグレーションとシードに十分なディスク容量があるか確認

## コマンドラインからのインストール

`dls:install` は、ブラウザを使わずにウィザードと同じ処理を実行します。ウィザードを開く
Web サーバーが無い場合や、インストールを自動化したい場合に使います。ワンライナー
インストーラはこの方法を使います。

```bash
php artisan dls:install \
    --site-name="My Site" \
    --admin-name=admin \
    --admin-email=admin@example.com \
    --url=example.com \
    --db=sqlite \
    --force
```

指定しなかった項目は対話で尋ねるので、手作業でも使えます。`--no-interaction` を付けた
場合、不足している項目は質問ではなくエラーになります。

### パスワード

`--admin-password` も使えますが、値がシェルの履歴とプロセス一覧に残ります。環境変数を
推奨します。

```bash
DIXLASE_ADMIN_PASSWORD='…' php artisan dls:install …
```

データベースとメールのパスワードは `DIXLASE_DB_PASSWORD` と `DIXLASE_MAIL_PASSWORD` で
同様に渡せます。対話実行の場合、管理者パスワードは画面に表示されずに入力できます。

### 実行を拒否する条件

次の場合、コマンドは何も書き込まずに停止します。

- すでにインストール済み（`INSTALLED=true`）
- 別の実行がロックを保持している（`storage/framework/install-running`）
- 必須項目が不足しており、対話が許可されていない
- ウィザードと同じ検証ルールに違反している
- **確認が取れていない。** 既定では対象データベースの全テーブルを削除して作り直すため、
  非対話実行には `--force` が必要です。削除せずにマイグレーションするには
  `--preserve-data` を付けます。

### データベース

`--db=sqlite`（既定）はファイルが無ければディレクトリごと作成します。パスは
`--db-database` で指定します。MySQL の場合は `--db-host` / `--db-port` /
`--db-database` / `--db-username` を渡します。データベース自体は事前に作成され、
ユーザーがそこにテーブルを作成できる必要があります。

### 完了後

サイトと管理画面の URL が表示され、`.env` は `INSTALLED=true` になります。ほかに必要な
操作はありません。ウィザードの完了画面が行う最終処理は、コマンドが済ませています。
